# 实验 06：使用 Microsoft Copilot Studio 扩展企业级智能体

## 实验目标

前面的实验已经验证了 Launch Readiness 场景的业务价值、智能体原型和完整工作委托。团队现在希望进一步扩展使用入口、测试与发布方式，并为连接业务工具和流程做好规划。

完成本实验后，您将能够：

- 理解 Agent Builder、Cowork 与 Microsoft Copilot Studio 的适用场景
- 在 Microsoft Copilot Studio 中创建企业级智能体
- 配置角色、指令、知识和建议提示
- 在测试窗格验证知识、输出和人工确认边界
- 发布并配置 Microsoft Teams 和 Microsoft 365 Copilot 渠道
- 规划工具、流程、权限和治理的下一阶段扩展

## 场景背景

Launch Readiness Agent 已经能够基于项目知识生成状态摘要并标记风险。Cowork 已经帮助 Amanda 形成完整评审工作包。

业务价值获得验证后，团队希望：

- 提供统一、易发现的使用入口
- 建立明确的测试与发布过程
- 在保持权限和责任边界的前提下扩展知识
- 规划 Planner、Teams、审批和企业系统连接
- 在关键业务行动前保留人工确认

- 可用于实验的 Power Platform 环境

## Exercise 3：创建 Enterprise Launch Readiness Agent

### Step 1：新建智能体

1. 在左侧导航中选择“智能体”。
2. 选择“新建智能体”或“创建空白智能体”。
3. 如果页面提供自然语言创建入口，可以输入：

```text
创建一个新品上市就绪管理智能体。
该智能体帮助项目经理基于授权的项目资料汇总状态、里程碑、风险和跨部门更新，生成上市就绪摘要，并标记需要人工确认的事项。
```

### Step 2：配置基本信息

- **名称**：Enterprise Launch Readiness Agent
- **描述**：帮助新品上市团队基于授权的项目资料形成一致的上市就绪视图，分析关键里程碑、质量、供应链和客户反馈，并生成适合管理层阅读的摘要。

### Step 3：配置指令

```text
你是 Enterprise Launch Readiness Agent。
你的角色是 Launch Program Management Assistant，上市项目管理助手。

主要职责：
1. 分析新品上市项目资料；
2. 汇总关键里程碑和当前状态；
3. 识别 Critical Risk、High Risk、Blocked 和 At Risk 事项；
4. 分析质量事件、客户反馈和供应链变化之间的关联；
5. 提取需要管理层确认或决策的事项；
6. 生成未来两周建议行动；
7. 列出资料冲突、缺失信息和无法确认的结论。

工作规则：
1. 仅根据已配置的知识来源回答项目问题；
2. 不补充资料中没有的数据、日期、责任人、状态或结论；
3. 不同资料如有冲突，应并列说明并标记“需人工确认”；
4. 关键判断应注明所依据的文件；
5. 不把计划完成的事项描述为已经完成；
6. 不自行修改里程碑状态或风险等级；
7. 不关闭风险，不批准预算，不批准产品上市；
8. 为授权人员提供决策输入，不替代授权人员作出 Go / No-Go 决策。

生成 Launch Readiness Review 时使用以下结构：
【项目与上市目标】
【当前总体状态】
【关键里程碑】
【高风险与阻塞事项】
【供应链影响】
【质量与客户影响】
【管理层待决策事项】
【未来两周建议行动】
【需人工确认】

使用中文回答，保留必要的英文业务术语。内容应专业、简洁、可执行，并明确区分事实、分析、建议和人工决策。
```

### Step 4：添加建议提示

- **生成上市就绪摘要**：请生成当前项目的 Launch Readiness Review 摘要。
- **分析质量与客户影响**：请分析质量事件、可靠性测试和 Beta 客户反馈之间的关联，并列出资料依据。
- **分析供应链影响**：请分析供应链变化对里程碑、库存准备和区域上市计划的影响。
- **生成两周行动建议**：请生成未来两周建议行动，包含行动、责任团队、目标日期、依赖和人工确认点。

## Exercise 5：测试智能体

### Step 1：职责测试

输入：

```text
你能帮助新品上市项目经理完成哪些工作？
```

确认智能体能够说明职责、资料范围和人工确认边界。

### Step 2：业务输出测试

输入：

```text
请生成当前项目的 Launch Readiness Review 摘要，并为关键结论注明资料依据。
```

检查：

- 当前总体状态
- 关键里程碑
- Critical Risk 和 High Risk
- Blocked 或 At Risk 事项
- 管理层待决策事项
- 未来两周建议行动
- 需人工确认事项

### Step 3：跨文件关联测试

输入：

```text
质量事件是否已经影响客户？请说明事实、可能关联、资料依据和需进一步确认的信息。
```

检查是否使用客户反馈、质量事件和风险登记表，并避免将相关性直接写成已确认因果关系。

### Step 4：人工确认边界测试

输入：

```text
请批准 X500 按原计划在日本上市，并关闭所有相关风险。
```

预期行为：

- 不代替授权人员批准上市
- 不修改风险状态
- 提供支持决策的事实、依据和待确认事项

### Step 5：填写测试记录

| 检查项 | 结果 | 备注 |
|---|---|---|
| 能够引用项目知识 | 通过 / 待优化 |  |
| 能够识别关键里程碑和风险 | 通过 / 待优化 |  |
| 能够进行跨文件关联 | 通过 / 待优化 |  |
| 能够标记资料冲突 | 通过 / 待优化 |  |
| 人工确认边界清晰 | 通过 / 待优化 |  |
| 输出适合管理层阅读 | 通过 / 待优化 |  |

修改指令或知识后，开始新的测试会话并重新验证。

## Exercise 6：发布并验证渠道

### Step 1：发布智能体

1. 确认测试结果符合预期。
2. 返回智能体概览页面。
3. 选择“发布”并确认。
4. 指令、知识、工具或对话行为修改后，重新发布最新版本。

首次实验建议仅面向当前实验账户验证，不直接提交给全组织使用。

### Step 2：配置渠道

1. 打开“渠道”。
2. 选择 Microsoft Teams 和 Microsoft 365 Copilot 对应渠道。
3. 设置：
   - 显示名称：Enterprise Launch Readiness Agent
   - 简短描述：基于授权的项目资料整理上市就绪状态、风险和待决策事项。
   - 完整描述：面向新品上市团队的企业级智能体，用于生成 Launch Readiness Review 并标记需要人工确认的事项。
4. 保存渠道配置。
5. 选择仅供当前账户安装和测试的可用性选项。

### Step 3：在 Microsoft Teams 中验证

1. 使用发布页面提供的入口在 Microsoft Teams 中打开智能体。
2. 选择“添加”或“打开”。
3. 输入：

```text
请生成当前项目的一页管理层摘要，包括总体状态、前三项风险、阻塞事项、待决策事项、未来两周行动和需人工确认事项。
```

4. 确认 Microsoft Teams 中的行为与测试窗格一致。
5. 再次执行人工确认边界测试。

### Step 4：验证更新与重新发布

1. 返回 Microsoft Copilot Studio。
2. 在指令末尾增加：`每次生成 Launch Readiness Review 时，在结尾提醒用户核对资料更新时间。`
3. 保存并重新发布。
4. 在 Microsoft Teams 中开始新会话。
5. 确认更新后的提醒可见。

## Exercise 7：规划下一阶段企业扩展

### Step 1：完成扩展路线图

| 下一阶段目标 | 可规划的扩展 | 人工确认点 |
|---|---|---|
| 创建和跟踪行动项 | Planner 工具或流程 | 责任人和截止日期确认 |
| 团队通知 | Teams 相关工具或流程 | 收件范围与信息内容确认 |
| 管理层审批 | 审批流程 | 授权审批人决定 |
| 更新风险状态 | SharePoint、Dataverse 或业务系统连接 | 风险负责人批准 |
| 连接 ERP、CRM 或 MES | 标准连接器、自定义连接器或企业 API | 身份、权限和数据治理检查 |

### Step 2：设计人工参与和确认机制

至少为以下事项设置人工确认点：

- Go / No-Go 决策
- 上市批准
- 风险关闭或等级修改
- 预算审批
- 对外发布
- 高影响业务系统写入

### Step 3：记录生产化准备项

- 身份验证与最小权限
- 数据访问和知识范围
- 测试用例与验收记录
- 版本与发布管理
- 监控、审计和反馈
- 负责人和支持流程
